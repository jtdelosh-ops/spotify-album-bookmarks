# Manual iPhone / Spotify release test plan

**Current result: NOT RUN.** The checks below require the real Spotify app/account, a reviewed HTTPS deployment, and a physical iPhone. Mark the actual date, app/OS versions, hostname, source commit, and outcome when executed. Do not record tokens or the setup key in results.

| Scenario | Steps / expected evidence |
| --- | --- |
| Setup and permissions | Verify Client ID allowlist/Premium, complete PKCE, and approve the two playback scopes. Confirm `/me` returns stable `account_id`. Inspect cookies without copying their values: Secure, HttpOnly, SameSite=Lax, Path=/. |
| Private instance | Signed-out browser cannot list bookmarks. Wrong setup key is refused. Original owner can reconnect; another Spotify account cannot replace that owner, even after disconnect. Use a test account only if one is available/approved. |
| Home Screen access | Keep an existing shortcut that opens the page, or use URL plus Open URLs. Verify it opens the deployed app with the browser session. Add/update/resume on the page must not require a separate Shortcut key or setup checkbox. |
| Capture accuracy | Note the playing/paused track and position, tap Add bookmark or Update position, and compare the saved value against Spotify. Record observed latency/tolerance rather than claiming exact synchronization. Test the start and end of a long track. |
| Independent saves and persistence | Save two points in the same album, including while paused, then save the same episode twice. Every save must create a different ID and leave earlier positions unchanged. Name one slot and verify its position/date/order and sibling slots stay unchanged. Clearing the name restores its automatic title. Confirm migrated album positions survive and all saves persist across sign-in/restart. |
| Updating an existing slot | Update a named slot while music is paused, then replace it with a podcast from another source. ID/name/creation date/order and siblings must stay unchanged; audio/position/edit date must change. Missing/unsupported playback must preserve the row. A concurrent rename must survive; deleting during capture must return404 without recreating the slot. Update a migrated album slot to other audio, then delete it: only its original recovery rows and chosen slot should disappear. |
| Legacy API access | Using the authenticated API, confirm an add-only credential cannot list/update even with a valid cookie. An opt-in replacement may list choices and update a save, but full library, rename, delete, devices, all resume routes and credential management remain denied. Rotation/revocation invalidate it. The website must not expose the retired key/checkbox workflow. |
| Album-context resume | Activate a desired Spotify device, tap Resume, and observe the actual album, track, and timestamp. Listen across the track boundary to confirm the album continues. Repeat with a disc-two track numbered 1 and with shuffle on/off; note shuffle's subsequent ordering. |
| No active device | With no active Spotify player, tap Resume and verify the device list refreshes without automatically choosing a target. Choose an available idle device and retry. Missing devices should prompt opening Spotify and refreshing. Do not claim the service wakes a closed app. |
| Explicit device | Refresh devices, choose a different available device, and resume a bookmark. Verify the selected device receives the album, track, and saved time. A disappeared device must produce actionable feedback; restricted devices must not receive commands. Shortcut credentials must not list devices or resume. |
| One Resume control | Each bookmark has exactly one Resume button on desktop and iPhone. On iPhone, This iPhone is initially selected and remains available when the idle phone is hidden. Select a speaker/computer and verify the same button uses ordinary remote playback without opening local Spotify. Refresh after the selected device disappears: retain it as unavailable and never fall back to an active speaker. Changing Where to play or refreshing must hide/invalidate an earlier Open Spotify preparation; cancel sends no playback command. |
| iPhone open-and-resume | With Spotify idle and hidden from the list, choose This iPhone under Where to play, tap Resume, then Open Spotify & resume. Leave Spotify visible; confirm the requested saved item and time without manually playing other audio. Repeat after remembering the phone and with a cold first discovery. Reject multiple new phones, a wrong/non-phone remembered ID, restricted devices, changed/deleted bookmarks and expired preparation. Confirm request protection survives Safari backgrounding; test cancelled preparation sends no resume. No key/checkbox setup section should appear. |
| Restricted device | If available, select a restricted device and confirm clear refusal. If no such device is available, record the test as unverified. |
| Paused/unsupported playback | Pause music and a podcast and save: valid reported positions should be saved without starting playback. Try no state, missing position, a local file, or an audiobook chapter: an error must preserve saved places. For podcast Resume, observe the actual episode and saved time on the selected client; command acceptance alone is insufficient. |
| Podcast show context and confirmation | Resume saves from two different shows and confirm the exact episode/device/time each time. Repeat with an older row whose context URI is an episode URI; show lookup must not change its position, name, or capture date. A successful play response followed by no item, wrong episode/device, paused playback, or wrong position must not return confirmed success. Unavailable metadata must fail without issuing a bare episode-URI command. |
| Lost connectivity | Disable network and try Add/update/resume: show clear failure without changing a saved position. Re-enable network and retry. For phone resume, a transport error is unconfirmed playback; check Spotify before retrying. |
| Legacy credential lifecycle | Through the authenticated API, rotate/revoke a credential and verify old clients fail. Verify no credential can call either resume route. Never share a populated API request as evidence. |
| Token lifecycle | Wait for natural access expiry or use a separate safe test setup to exercise refresh. Revoke Spotify authorization and confirm reconnect feedback; sign in again and verify saved bookmarks remain. Six-month expiry is covered by mocked `invalid_grant` locally; do not claim six months of observation. |
| Error handling | Real 403/429/quota exhaustion should not be induced by flooding Spotify. Use mocked checks for these conditions and record genuine occurrences only. Confirm `Retry-After` is surfaced, with no retry loop. |
| Delete and disconnect | Delete one of several bookmarks in the same content and verify only that slot disappears after reload. Deleting a new slot must preserve the migrated slot's recovery data; deleting the migrated slot must clear its own recovery rows. Disconnect should clear Spotify credentials, sessions, and Shortcut access while retaining bookmarks. Reconnect as the same owner. |
| Mobile layout/accessibility | Inspect small and large iPhone widths, long album/track names, text scaling, focus/tap targets, empty list, multiple cards, visible feedback, and VoiceOver names for Resume/Delete. |

Release can proceed only with an honest account of failed and unavailable checks. Passing mocked tests is not a substitute for observing successful Spotify playback and the iPhone app-opening flow on the intended device.
