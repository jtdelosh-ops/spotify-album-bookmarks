## Verified official documentation

| Area | Finding and design consequence | Official source |
| --- | --- | --- |
| Development access | Personal/single-account apps are supported. App owner must retain Premium; development apps allow up to five authenticated users, with explicit allowlisting. Extended access has organization requirements and is unnecessary for this MVP. | [Quota modes](https://developer.spotify.com/documentation/web-api/concepts/quota-modes) |
| Recent quota change | July increased the development Client ID cap to 25. Quotas are shared per developer account; this supersedes older February guidance mentioning one Client ID. `QUOTA_EXCEEDED` distinguishes quota exhaustion from ordinary rate limiting. Numeric quotas and bucket groupings are not a reliable public constant. | [23 July update](https://developer.spotify.com/blog/2026-07-23-web-api-quota-updates) |
| Endpoint availability | Current development documentation retains playback state, start/resume, and current-user profile. This app does not depend on removed batch/catalog fields. | [February endpoint changelog](https://developer.spotify.com/documentation/web-api/references/changes/february-2026) |
| Playback capture | `GET /me/player` supplies track metadata, `progress_ms`, `is_playing`, and device information. It may return 204 or null item/progress. `timestamp` indicates the last state change; it is not a freshness heartbeat, so a long track is not rejected just because that timestamp is old. | [Get Playback State](https://developer.spotify.com/documentation/web-api/reference/get-information-about-the-users-current-playback) |
| Resume | Premium is required. The play endpoint accepts an album `context_uri`, a track URI in `offset`, and `position_ms`, with optional `device_id`. One combined request avoids ordering assumptions between play and seek. Acceptance is not proof that a physical device played successfully. | [Start/Resume Playback](https://developer.spotify.com/documentation/web-api/reference/start-a-users-playback) |
| Permissions | Request `user-read-playback-state` and `user-modify-playback-state`. Identity uses the public stable account identifier returned by `/me`, without requesting email or private profile fields. Confirm this minimal-scope combination against the actual existing app during live OAuth. | [Playback state](https://developer.spotify.com/documentation/web-api/reference/get-information-about-the-users-current-playback), [play](https://developer.spotify.com/documentation/web-api/reference/start-a-users-playback), [current profile](https://developer.spotify.com/documentation/web-api/reference/get-current-users-profile) |
| Stable ownership | May added immutable `account_id` and directs services to use it for account linking instead of mutable `id`. The schema follows this newer requirement. Missing `account_id` fails closed. | [May changelog](https://developer.spotify.com/documentation/web-api/references/changes/may-2026) |
| OAuth | PKCE supports S256 challenge, code verifier, matching redirect URI, and token refresh. HTTPS is required except explicit loopback IPs; `localhost` is not allowed. | [PKCE](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow), [redirect URIs](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri) |
| Token lifetime | Refresh tokens require reauthorization after six months; refreshing access does not extend that lifetime. An `invalid_grant` response must discard the refresh credential and trigger sign-in, without retrying it. Rotation is stored; omitted replacement refresh tokens retain the existing value. | [June announcement](https://developer.spotify.com/blog/2026-06-18-refresh-token-expiration), [refreshing tokens](https://developer.spotify.com/documentation/web-api/tutorials/refreshing-tokens) |
| Rate limiting | Spotify uses a rolling 30-second rate window, with mode-dependent limits. Honor `Retry-After`; do not invent a reset time for development quota exhaustion. Save/resume make calls only on user action. | [Rate limits](https://developer.spotify.com/documentation/web-api/concepts/rate-limits) |
| iOS transport | Apple's Get Contents of URL supports POST and JSON bodies. Header entry, first-run network permission, notifications, and one-tap Home Screen/widget execution require device validation. Notification envelope mode avoids depending on non-2xx handling to reach Show Notification. | [Apple Shortcuts API requests](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios) |
| Hosting | Worker static assets can pass through the Worker first; D1 supports bindings, prepared statements, and SQL migrations. One Worker serves the API and public shell with private authenticated data. | [Asset binding](https://developers.cloudflare.com/workers/static-assets/binding/), [D1 API](https://developers.cloudflare.com/d1/worker-api/), [migrations](https://developers.cloudflare.com/d1/reference/migrations/) |
